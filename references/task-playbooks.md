# 七类任务的操作手册

> 每条任务给四样东西：触发条件、输出结构、篇幅与节奏、禁止事项。
> 通用规范（先结论、概念给判据、四种陈述要分开）见 SKILL.md §3，本文件不重复。

---

## §1 科普与概念答疑

**触发**：「什么是 X」「X 和 Y 有什么区别」「这个概念是谁提的」「能不能举个例子」。

**输出结构（四段，固定顺序）**

1. **一句话定义**（可被反驳的那种，不是「强调技术与社会的互动」）。
2. **它反对什么**：这个概念出现时，是在反驳哪一种既有说法。这一步最容易被跳过，但没有它，定义就没有边界。
3. **一个具体例子**：三句话以内，最好是日常可感的场景。
4. **常见误用**：一句到两句，写成可识别的症状（「论文里出现 X 句式，就是犯了 Y」）。

**篇幅**：200–400 字。用户追问「再展开」时才加第五段（与相邻概念辨析）与第六段（另一条路线怎么看）。

**禁止**
- 不要一上来给学科史。
- 不要一次讲三个概念。用户问一个，就答一个。
- 不要把定义写成同义反复（「数字劳动就是数字时代的劳动」）。
- 不要在科普里塞文献。用户要出处时再给，且必须给得起。

**句式模板**
> X（English）指的是：**〔一句可被反驳的判据〕**。它要反驳的是〔既有说法〕。典型情形是〔三句话的场景〕。最常见的错用是把它当成〔相邻概念〕——两者的分界在〔一句判据〕。

## §2 解读现象（本 skill 最常用的任务）

**触发**：「用数字社会学解释××」「这个现象怎么从社会学角度看」「帮我分析这个案例」。

**前置动作**：按 `route-selection.md` §3 问一次路线。用户已指定路线则跳过。

**输出结构（七步骨架）**

1. **现象的可争议点**（2–3 句）。不是描述现象，而是指出它为什么值得解释：哪两个常识在这里冲突。
2. **本路线的分析单位**（1 句）。说明在这条路线里，什么算「一件事」——一条钱流、一个决策点、一组位置差异，还是一份数据的生成机制。
3. **机制**（3–5 段）。每段一个环节，段首句是机制陈述，段内给条件（在什么情况下成立）与反例（什么情况下不成立）。
4. **可检验的推论**（2–4 条）。写成「如果机制成立，应当观察到 X；如果观察到 Y，机制被限定」。这一步把评论变成研究。
5. **这条路线看不到什么**（2–3 句）。明写缺口，并指出缺口该由哪条路线补。
6. **中国语境的调整**（若对象在中国）。指认哪个前提不成立，给替代写法。
7. **一句话结论**。可被反驳，可被记住。

**篇幅**：1,200–2,500 字。用户要「短一点」时压缩第 3 步到两段，但第 1、4、5 步不能删——它们是这段分析的价值所在。

**禁止**
- 不要四条路线各写一段然后说「综合来看」。这是最典型的四不像。
- 不要用「技术是一把双刃剑」「利弊并存」收尾。
- 不要在机制段里塞形容词（「深度」「全面」「深刻」）。
- 不要把案例当分布（见 SKILL.md 红线 3）。

**质量自检（三条，缺一即重写）**
- 第 4 步的推论能不能被别人拿数据打掉？打不掉说明写的是态度不是推论。
- 第 5 步的缺口是不是真的存在？若说不出来，说明这条路线被用超了。
- 全文有没有一句话是「只要换个立场就反过来说也成立」？有就删。

## §3 专业答疑（方法、设计、判断类）

**触发**：「我这个设计行不行」「这样测量有没有问题」「审稿人说我没识别策略，怎么回」「这个说法现在还算数吗」。

**输出结构**

1. **判断先给**（1–2 句）：行 / 不行 / 有条件地行。不要先复述问题。
2. **判据**（2–4 条）：这个判断依据哪几条可检查的标准。判据要能被用户拿去自查。
3. **最可能的攻击点**（2–3 条）：审稿人或答辩会从哪里打，按可能性排序。
4. **修改方案**（分档）：最小改动（不改设计，只改表述）／中等改动（补一项材料或一个对照）／大改（换设计）。明确说清每档的代价。
5. **若无法修改**：给「降级写法」——把强主张改成条件命题，并说明这样改会损失什么。

**篇幅**：600–1,200 字。

**禁止**
- 不要用「这取决于你的研究问题」开头。那是把判断推回给用户。
- 不要给「多读文献」这类无法执行的建议。
- 不要在用户只要「行不行」时输出三千字方案。

**三类高频问题的固定答法**
- **「样本太小」** → 先问推断目标：若是机制存在性，小样本可接受但须交代抽样逻辑；若是总体比例，小样本不可接受，须改问题。
- **「没有因果识别」** → 先问主张强度：若主张是「机制存在」，描述性证据够；若主张是「效应大小」，必须补对照。改法优先「弱化主张」而不是「硬加模型」。
- **「概念用错了吗」** → 用 `glossary.md` 的「常见误用」项逐条比对，指出症状而非态度。

## §4 系统学习（含精读导读）

**触发**：「带我学数字社会学」「列一个阅读计划」「这本书讲了什么」「帮我搭知识框架」。

**输出结构**

1. **先给地图**（一张表）：四条路线 + 各自的核心问题 + 各自最典型的材料类型。不超过 12 行。
2. **两条路径供选择**：四周速成（每天 1–1.5 小时）与十二周系统（每周 1 个主题 + 1 个产出物）。两条都给，让用户选。
3. **逐周安排**：主题 → 读什么类型文本（**不列书名**，给类型与判据，例如「一本学科导论 + 两篇方法综述」）→ 产出物（一页笔记、一张判据表、一段 300 字的机制陈述）。
4. **三个自测题**：学完这一周，能不能回答。答不上就回读。

**篇幅**：800–1,500 字。

**精读导读的七段式**（用户问「这本书讲什么」时用）
1. 它在解决什么问题（3 句）。
2. 它的对手是谁（反驳哪种既有说法）。
3. 论证链条（4–6 步，每步一句）。
4. 最硬的三个概念（定义 + 判据）。
5. 它的证据类型与强度（能支撑什么、不能支撑什么）。
6. 可迁移到中国语境的接口（2–3 条，注明前提）。
7. 读完该拿它干什么（写论文时用在哪一节）。

**禁止**
- **不要列具体书名与作者**。给类型与判据，用户自己去找；若用户明确要求书目，说明本 skill 不含书目，另找目录工具。
- 不要把学习计划排满。每天留白，每周留一天不安排（这是用户的硬偏好）。
- 不要用「先读经典再读前沿」这种无信息量的顺序。

## §5 选题探讨与评估

**触发**：「我想研究××，有什么选题」「这个题目行不行」「帮我想几个可做的方向」。

**前置动作**：先问路线（或按材料默认）。选题的可行性有一半取决于路线。

**输出结构**

1. **把用户的题目改写成可检验形式**（1 段）。原题通常是「××对××的影响」，改写后要指出：分析单位、变异来源、可观测指标。
2. **3–5 个候选选题**，每个给五要素：
   - 一句话问题（含分析单位与变异来源）
   - 需要的材料与获取难度（高／中／低，注明为什么）
   - 主要竞争（这个方向已有人做到什么程度，用 `debates.md` 判断哪条战线还开着）
   - 贡献类型（新机制／新测量／新案例／新解释）
   - 最大风险（数据、伦理、审稿）
3. **四维评估矩阵**：可做性（材料是否可得）、区分度（与既有研究的差别）、理论回报（能否改写一个判据）、发表适配（中文刊／英文刊更认哪一类）。每维 1–5 分，**给分要给理由**，不要只给总分。
4. **推荐 1–2 个**，说明理由，并给「如果你只有三个月」的缩小版。
5. **淘汰理由**：明确写出哪几个不建议做，为什么。

**篇幅**：1,000–1,800 字。

**禁止**
- 不要给「填补空白」式选题（「国内尚缺乏××研究」不是理由，缺研究可能是因为做不了）。
- 不要给无法在中国取数的题（平台内部数据、需行政许可的数据）。
- 不要回避竞争：若某个方向已有强研究，直接说，并给「绕开」而非「硬碰」的方案。

**选题的三个生成器**（比空想有效）
- **失效点生成器**：拿一条路线的 §9（中国失效点），把「某前提在中国不成立」直接变成题目。
- **外生变化生成器**：找一个政策或技术的外生时点（试点、互联互通、费率调整、设备降价），做前后对照。
- **争议生成器**：从 `debates.md` 找「可裁决性高但缺证据」的争论，去做那个缺的证据。

## §6 论文写作

**触发**：「帮我写引言」「理论框架怎么写」「方法节」「这段怎么改」。

**前置动作**：**必须问路线**。不同路线的理论框架、方法节、贡献陈述完全不同，写错路线等于重写。

**输出结构**

1. **先确认三件事**：投什么刊（中文／英文）、字数上限、现有材料清单。缺一项就先问。
2. **给骨架（段落级）**：每段一句功能说明（这段干什么、必须出现什么），不给整段成文——除非用户明确要成文。
3. **给 2–3 个可套用的句式**（中英各一套，按用户语言选）。
4. **标注风险句**：哪些句子会被审稿人抓（因果表述、概念混用、中国例外论）。

**篇幅分配（可直接用）**

| 部分 | 中文 1.2 万字 | 英文 8,000 词 | 必须出现的东西 |
|---|---|---|---|
| 引言 | 1,200–1,500 | 700–900 | 一个可争议的现象 + 一个明确缺口 + 一句贡献 |
| 文献与框架 | 2,500–3,000 | 1,500–1,800 | 一条战线的两侧 + 本研究的立场 + 1 个判据表 |
| 数据与方法 | 2,000–2,500 | 1,200–1,500 | 材料生成机制 + 抽样逻辑 + 效度威胁自查 |
| 发现 | 4,000–5,000 | 2,500–3,000 | 每组发现先给判据再给材料 |
| 讨论 | 1,500–2,000 | 900–1,100 | 三条机制陈述 + 两条边界 + 一条反例 |
| 结论 | 600–800 | 300–400 | 一句可被引用的话，不重复摘要 |

**四条硬规矩**
1. **引言不要从「随着……的发展」开始**。第一句就给现象里的矛盾。
2. **文献不要写成「A 说、B 说、C 说」**。写成「一条战线的两侧 + 第三种可能」。
3. **方法节必须写「材料是怎么被生产出来的」**。平台数据要写清界面如何诱导行为；调查数据要写清谁不在样本里。
4. **贡献不要写「丰富了研究」**。要写「改写了哪一个判据」或「提供了一个此前无法测的量」。

**句式（中文）**
- 现象句：「〔现象〕看起来是〔常识解释〕，但它同时伴随〔反常事实〕。」
- 缺口句：「已有研究多从〔视角〕处理这一问题，其代价是无法说明〔具体环节〕。」
- 判据句：「本文把〔概念〕操作化为三项可观察指标：〔A〕、〔B〕、〔C〕；三者同时成立才计入。」
- 限定句：「这一结论只在〔条件〕下成立；当〔条件〕不成立时，预期观察到〔相反结果〕。」

**句式（英文）**
- `X is usually read as Y, yet the same evidence also supports Z.`
- `Existing work explains A but leaves B unaccounted for, because it treats C as exogenous.`
- `I operationalise X as three observable indicators; only cases satisfying all three are coded as instances.`
- `The claim holds under condition C; where C fails, the expected pattern reverses.`

**禁止**
- 不要替用户编数据、编引注、编页码。
- 不要在用户没给材料时写出「本研究发现……」的成句。
- 不要在英文稿里用「we」当单作者（用户习惯用单作者人称：本文／本研究／I）。
- 不要一次改全文。按节改，改完一节确认一节。

## §7 论文评审

**触发**：「看看这篇论文怎么样」「打个分」「这篇能投哪里」「审稿意见怎么回」。

**输出结构**

1. **一句话判断**（含分数）：可发表 / 大修 / 拒稿 + 分数（百分制）。先给结论。
2. **路线判定**（1 句）：这篇实际走的是哪条路线（可能与他自称的不同）。判错的稿子，评审意见会全打偏。
3. **分数构成表**：按 `review-rubric.md` 的五维给分，每维给一句话理由。
4. **三段评语**：① 它做对了什么（1 段，具体到段落或机制）；② 致命问题（1–3 条，按严重度排序，每条给「为什么致命」与「最小修复」）；③ 可改但不致命（列表）。
5. **提升路径**：从当前分数到下一档，需要改哪三处，按性价比排序。
6. **投稿建议**（若用户问）：按路线与贡献类型给 2–3 类刊物定位（**不给具体刊名与影响因子**，避免过时与误导）。

**篇幅**：800–1,500 字。打分必须给，且要敢给低分——用户明确要求不许只报好消息。

**禁止**
- 不要用「本文选题有意义，但……」开头（这是最没有信息量的评审句式）。
- 不要跨路线扣分（见 SKILL.md Gotchas 第 9 条）。
- 不要用「建议补充近五年文献」这类无法执行的评语。
- 不要在评审里替作者重写论文。

**回复审稿意见的三段式**
1. **逐条回应**：原文引述 → 我们的判断（接受／部分接受／不接受）→ 改动位置（页码或小节）。
2. **不接受的要有理由**：给判据，不给态度（「该建议预设了 X，而我们的设计是 Y，因为 Z」）。
3. **集中改动要说明连带影响**：改了识别策略，结论强度、摘要、局限三处必须同步改，并在回复信里点明。
